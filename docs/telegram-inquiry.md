# 텔레그램 봇 두 개 — 무엇이 무엇인가, 어떻게 켜는가

## 한 장 요약

| | **알림 봇** `@icartsh_answer_bot` | **문의 봇** `@icartsh_ib_bot` (표시명 `icartsh_IB`) |
|---|---|---|
| 방향 | 서버 → 사장님 | 고객 → 사장님 → 고객 |
| 무엇이 오나 | `🔔 새 상담 신청` (신청 폼 리드) | `💬 새 텔레그램 문의` (고객이 직접 쓴 글) |
| 주소 공개 | **절대 안 됨** | 페이지의 "텔레그램 문의" 버튼 |
| 환경변수 | `TELEGRAM_BOT_TOKEN` | `TELEGRAM_INQUIRY_BOT_TOKEN` |
| 코드 | `server/sinks.mjs` | `server/telegram-inquiry.mjs` + `api/telegram.js` |

**새 봇을 만들 필요는 없다.** 두 개 다 이미 있다.

## 왜 하나로 못 쓰나

봇 하나에 두 방향을 다 태우면 두 가지가 깨진다.

1. **리드가 남에게 간다.** 알림 봇은 목적지(`chat_id`)를 정하지 못하면 "봇에게 온 최근 대화"에서
   찾아낸다. 봇 주소를 페이지에 걸면 고객이 그 대화 목록에 들어오고, 그 다음 리드 알림이
   **이름과 전체 전화번호를 달고 그 고객에게** 간다. 화면에는 아무 이상이 없다.
   구글 시트가 꺼져 있는 동안 텔레그램이 유일한 기록이라, 그 리드는 사장님 쪽에 아예 안 남는다.
2. **webhook 과 getUpdates 는 같이 못 쓴다.** 문의를 받으려면 webhook 을 걸어야 하는데,
   webhook 이 걸린 봇에는 `getUpdates` 가 409 로 막힌다 — 알림 봇의 목적지 자동 탐색이 그걸 쓴다.

지금은 (1)에 잠금이 걸려 있다. 알림 봇에 대화가 둘 이상이면 **보내지 않고 접수를 거절한다.**
리드 한 건을 잃는 쪽이 남의 번호가 새는 쪽보다 낫다 — 잃은 리드는 보이지만 새어 나간 번호는 안 보인다.
잠금이 걸리면 신청 폼이 "지금 접수가 어렵다"를 내보내므로 유입이 있어도 리드가 0이 된다.
**`TELEGRAM_CHAT_ID` 를 고정해 두면 이 잠금은 영원히 걸리지 않는다.**

## 켜는 순서 (10분)

### 0. 먼저 무엇이 남았는지 본다

```bash
npm run telegram -- doctor
```

여섯 가지(알림 봇 토큰 / `chat_id` / 문의 봇 토큰 / webhook 비밀값 / webhook 등록 / 사장님의
START)를 한 번에 짚고 **남은 것만 순서대로** 알려 준다. 값을 하나 넣을 때마다 다시 돌리면 된다.
"남은 것 없음" 이 나올 때까지가 설정이다.

여섯 개 중 하나만 빠져도 **화면에는 아무 이상이 없다.** 버튼은 눌리고, 고객 쪽에는 전송된
것으로 보이고, 오류도 안 뜬다. 빠진 것이 무엇이냐에 따라 결과만 조용히 달라진다 — 문의가
사라지거나, 리드 접수가 멈추거나, 답장이 안 나간다. 그래서 눈으로 확인하지 않는다.

### 1. 사장님 `chat_id` 를 고정한다 — 이것부터

1. 텔레그램에서 **@icartsh_answer_bot** 에게 아무 말이나 보낸다.
2. `npm run telegram -- doctor` 를 돌린다. 2번 항목에 `TELEGRAM_CHAT_ID=숫자` 가 그대로 나온다.
3. Vercel → Project Settings → Environment Variables 에 그 값을 넣는다.

> 브라우저로 `https://api.telegram.org/bot<알림봇_토큰>/getUpdates` 를 열어도 같은 값이 나오지만,
> 그러면 **토큰이 방문 기록과 자동완성에 남는다.** 봇 토큰 하나면 그 봇으로 아무에게나 메시지를
> 보낼 수 있다 — 우리 경우 고객 대화 전부가 거기 붙어 있다. `doctor` 는 그 주소를 띄우지 않는다.

### 2. 문의 봇 토큰을 넣는다

@BotFather → `/mybots` → **icartsh_IB** → *API Token*.
Vercel 환경변수에 `TELEGRAM_INQUIRY_BOT_TOKEN` 으로 넣는다.

### 3. webhook 비밀값을 만든다

```bash
openssl rand -hex 24
```

나온 값을 `TELEGRAM_WEBHOOK_SECRET` 으로 넣는다. 이 값이 없으면 `/api/telegram` 은 503 으로 닫혀 있다 —
공개 주소라서 확인 없이 열면 누구나 가짜 문의 카드를 만들어 넣을 수 있고, 거기에 답장하면
답변이 엉뚱한 사람에게 간다.

### 4. 재배포하고 webhook 을 등록한다

환경변수는 **새 배포부터** 적용된다. 기존 배포에 소급되지 않는다.

```bash
# 로컬 .env 에도 같은 값을 넣은 뒤
npm run telegram -- set https://ib-mt5-landing.vercel.app/api/telegram
npm run telegram -- status
```

### 5. 사장님이 문의 봇에도 `/start` 를 한 번 누른다

`@icartsh_ib_bot` 을 열고 START. 이걸 안 하면 봇이 사장님에게 말을 걸 수 없어서
**문의가 도착해도 전달되지 않는다.** (텔레그램은 사람이 먼저 말을 건 상대에게만 봇이 메시지를 보낼 수 있다.)

### 6. 확인

```bash
npm run telegram -- doctor        # "남은 것 없음" 이 나와야 한다
curl -s https://ib-mt5-landing.vercel.app/api/health | python3 -m json.tool
```

`sinks.inquiry.ready` 가 `true`, `sinks.telegram.destination` 이 `"pinned"` 면 정상이다.
그리고 다른 계정(또는 지인 휴대폰)으로 `@icartsh_ib_bot` 에 "테스트" 를 보내 본다 —
사장님 텔레그램에 `💬 새 텔레그램 문의` 카드가 떠야 한다.

## 쓰는 법

- 문의가 오면 카드가 뜬다. **그 카드에 답장(reply)하면 그대로 고객에게 간다.**
  카드 맨 아래 `#c숫자` 가 답장 대상 표식이다. 지우거나 고치면 안 된다.
- 카드가 아닌 곳에 그냥 쓰면 아무 데도 안 간다 (봇이 "전달할 대상을 찾지 못했습니다"라고 답한다).
- 전달에 실패하면 이유가 온다. `차단` 이라고 뜨면 텔레그램으로는 닿지 않으므로 전화로 가야 한다.
- 사진·파일은 전달되지 않는다. "텍스트가 아닌 메시지" 알림만 오고, 내용은 봇 대화창에서 직접 본다.

## 고장났을 때

| 증상 | 원인 | 확인 |
|---|---|---|
| 문의가 아예 안 온다 | webhook 미등록 / 도메인 변경 | `npm run telegram -- status` 의 `webhook 주소`, `최근 배달 오류` |
| 문의는 오는데 답장이 안 간다 | 카드가 아닌 곳에 답장했다 | 봇이 보내는 안내 문구 확인 |
| 신청 폼이 "접수가 어렵다"만 낸다 | 알림 봇에 대화가 둘 이상 | `/api/health` 의 `sinks.telegram.detail` |
| 사장님에게 카드가 안 오는데 오류도 없다 | 사장님이 문의 봇에 `/start` 안 함 | 위 5단계 |

## 검사

```bash
npm run smoke-telegram
```

위조 표식(고객이 자기 메시지에 `#c<남의 id>` 를 심어 답장을 가로채려는 경우), 인증 없는 요청,
고객 차단, 설정 누락, 도배까지 38건을 확인한다.
